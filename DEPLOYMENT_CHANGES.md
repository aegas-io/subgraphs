# Dockerfile Updates for Self-Hosted Graph Node Deployment

## Summary

Modified the Dockerfile to use a **two-stage build pattern** similar to the main analytics subgraph, enabling deployment to a self-hosted Graph Node instance.

---

## Key Changes

### 1. **manager.py Already Does Everything**

The `scripts/manager.py` script (lines 522-523) already handles:
- ✅ `prepare_module()` - Generates `schema.graphql` and `subgraph.yaml`
- ✅ `graph codegen` - Generates TypeScript types from schema
- ✅ `graph build` - Compiles AssemblyScript to WASM

So we **do NOT need** separate codegen/build steps in the Dockerfile!

### 2. **Two-Stage Build Pattern**

#### **Stage 1: Builder**
```dockerfile
# Install dependencies (Python, Node.js, graph-cli)
# Copy project files
# Run manager.py (does prepare + codegen + build in one command)
RUN python3 scripts/manager.py configs/perps/coti.json perps/analytics
```

#### **Stage 2: Deployment**
```dockerfile
# Minimal Node.js image
# Copy built artifacts from Stage 1
# Add deploy.sh script
ENTRYPOINT ["./deploy.sh"]
```

## File Structure After Build

When `manager.py` runs from `/build`, it creates:

```
/build/
├── subgraph.yaml          ← Generated by manager.py
├── schema.graphql         ← Generated by manager.py
├── build/                 ← Compiled WASM (graph build)
├── generated/             ← TypeScript types (graph codegen)
├── abis/                  ← Copied ABI files
└── perps/
    └── analytics/
        ├── src_symmio_0_8_4.ts
        ├── src_feeCollector_1.ts
        └── handlers/
```

**Important:** The build happens in the **root directory** (`/build`), not inside `perps/analytics`, because `subgraph.yaml` gets created in the root and references files like `./perps/analytics/src_*.ts`.

## How Deployment Works

### 1. **Container Startup**
```bash
docker run -e GRAPH_NODE_URL=http://localhost:8020 \
           -e IPFS_URL=http://localhost:5001 \
           -e SUBGRAPH_NAME=coti-perps-analytics \
           -e VERSION_LABEL=v0.0.1 \
           graph-deployer:latest
```

### 2. **deploy.sh Executes**
```bash
# Create subgraph namespace
graph create --node $GRAPH_NODE_URL $SUBGRAPH_NAME

# Deploy (uploads to IPFS and registers with Graph Node)
graph deploy --node $GRAPH_NODE_URL --ipfs $IPFS_URL $SUBGRAPH_NAME
```

### 3. **What `graph deploy` Does**
1. Packages `subgraph.yaml`, `schema.graphql`, `build/*`, ABIs
2. Uploads package to IPFS (`http://localhost:5001`)
3. Returns IPFS hash (e.g., `QmXXXXXX`)
4. Registers subgraph with Graph Node:
   ```
   POST http://localhost:8020
   { "name": "coti-perps-analytics", "ipfs_hash": "QmXXXX..." }
   ```
5. Graph Node fetches files from IPFS and starts indexing

## Testing Locally

### Build the Image
```bash
cd subgraphs-1
docker build -f Dockerfile.new -t graph-perps-deployer:latest .
```

### Run with Docker Compose

Add to your `docker-compose.yml`:
```yaml
services:
  perps-deployer:
    build:
      context: ./subgraphs-1
      dockerfile: Dockerfile.new
    container_name: perps-deployer
    environment:
      GRAPH_NODE_URL: "http://graph-node:8020/"
      IPFS_URL: "http://ipfs:5001"
      SUBGRAPH_NAME: "coti-perps-analytics"
      VERSION_LABEL: "v0.0.1"
      KEEP_CONTAINER_ALIVE: "false"
    depends_on:
      graph-node:
        condition: service_started
      ipfs:
        condition: service_healthy
    networks:
      - graph-network
```

## Troubleshooting

### Build fails at manager.py step
- **Check:** Is `configs/perps/coti.json` present?
- **Check:** Are ABI files in `configs/abis/`?
- **Fix:** Run `./scripts/clean.sh` before building

### Deployment fails with "database does not exist"
- **Cause:** PostgreSQL database not initialized
- **Fix:** Create database before deploying (see main project notes)

### IPFS connection refused
- **Cause:** IPFS container not started or not healthy
- **Fix:** Ensure IPFS healthcheck passes before deployer starts
